# 产品方案六问

这套框架用于统一产品需求定义和 PRD 编写的论证主线，但两个 skill 对六问的责任深度不同。

| 关键问题 | 要回答什么 | 最低质量要求 |
|---|---|---|
| 基于现状 | WHO、WHEN / WHERE、WHY / WHAT、当前 HOW、HOW MUCH | 事实有依据；数据有口径；覆盖主要角色和用户类型 |
| 预期目标 | 希望哪些用户或业务状态发生变化 | 目标对应问题；说明覆盖范围；有目标值或补数计划 |
| 业务方向 | 有哪些解法，为什么选择当前方向 | 至少比较真实可选项；说明成功依赖、投入、风险和未选原因 |
| 实现路径 | 方案通过哪些阶段、角色、信息和动作落地 | 需求定义确认关键阶段和重大约束；PRD 展开完整流程与分支，并关联原型或设计节点 |
| 判断标准 | 什么结果出现时认为方案有效 | 需求定义提出成功假设；PRD 固化结果与护栏阈值 |
| 验证指标 | 如何观察行为变化并验证判断 | PRD 定义口径、基线、目标、数据源、周期和负责人 |

## 逻辑链

```text
事实与证据
  → 问题定位
  → 目标状态
  → 方向比较与选择
  → 实现路径
  → 原型 / 设计与功能规格
  → 研发验收
  → 效果判断
  → 数据验证与复盘
```

每一层都应能回溯上一层：目标对应问题，方案对应目标，功能对应方案，验收对应功能，指标对应目标。

## Skill 责任边界

| 维度 | `pm-requirement-define` | `pm-prd-write` |
|---|---|---|
| 核心问题 | 为什么做、改变什么、选什么方向、做到哪里 | 具体怎么实现、如何处理所有分支、如何验收和上线 |
| 事实与问题 | 分析并确认 | 摘要引用并保持可追溯 |
| 目标与非目标 | 定义并确认 | 固化，不擅自改变 |
| 方案方向 | 发散、比较和选择 | 引用已确认方向与既有选择依据，不补做方案比较 |
| 范围 | 定义一级产品范围，已知时交接主要入口和主路径 | 拆成功能、页面、版本和交付范围；页面或流程变化时补充动线和信息结构 |
| 状态 / 权限 / 异常 | 识别是否涉及及重大约束 | 完整展开矩阵、规则和兜底 |
| 联动 / 数据 / 兼容 | 扫描影响维度 | 定义详细处理方式和依赖 |
| 原型 / 设计文件 | 只在方向判断需要时使用低成本验证 | 建立资产索引，关联场景、功能、规则与验收 |
| 成功与指标 | 定义方向级成功假设 | 定义口径、基线、目标、数据源和观察周期 |
| 验收 | 不编写研发验收用例 | 编写可执行的 Given / When / Then |
| 退出条件 | 产品决策 `ready` | 交付规格 build-ready |

两者允许“信息重复”，但不允许“工作重复”：PRD 为了自包含可以摘要背景、目标和方向，但不能重新承担问题定义和方案选择。

## 三类标准

### 研发验收标准

判断功能是否按文档正确实现，关注流程、状态、权限、异常、数据和联动。

### 效果判断标准

判断方案是否产生预期用户或业务结果，通常使用结果指标和护栏指标。

### 验证指标

规定如何测量，包括行为或过程指标的定义、基线、目标、数据来源、观察周期和负责人。

## 四个质量门

1. 问题成立：事实、影响和需求主体清楚。
2. 方向可决策：目标、备选方向、取舍和假设清楚。
3. 方案可实现：范围、流程、功能、原型关联、规则和质量边界清楚。
4. 结果可验证：研发验收、成功标准和验证方案清楚。
