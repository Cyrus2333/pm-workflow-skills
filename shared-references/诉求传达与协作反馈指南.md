# 诉求传达与协作反馈指南

> 本文档回答一个问题：**需求方（人）如何把方向、文案、样式、体验等诉求高效传递给 AI**，让产物更快收敛到预期。
> 何时读取：方向探索与方案讨论阶段（pm-requirement-define）、原型生产与视觉打磨阶段（pm-prototype-deliver）、任何涉及用户可见文案的交付阶段（pm-prd-write / pm-collaboration-deliver）。
> 来源说明：本文方法提炼自探索页体验原型案例（见文末），其中所有效率数据为**首个案例的观察值，待更多案例校准**，不作为定律引用。

## 1. 五种诉求传达通道

同一轮反馈可以用不同方式给出，收敛效率差异极大。按从"定方向"到"改细节"排列：

### 1.1 概念锚点（定方向）

用一组核心概念作为每轮讨论的校准基准，例如某案例中的"展览感 / 家园感""看见别人，也看见自己""大气、简洁、不俗气"。

使用要点：**少说、说准、反复引用**。锚点一旦确定就不频繁换词——每次换一套新词，等于让 AI 重新猜方向。概念锚点确定后应随需求定义交接给下游所有环节。

### 1.2 参照物输入（效率最高）

直接提供竞品截图、参照方案、真实素材、台账数据等实体材料，并说明"这份材料传递的是什么诉求"。一次准确的参照物输入胜过十轮口头描述，应当**作为开工前的第一输入前置**，而不是迭代中期的补救。

### 1.3 元素级指令（执行最快）

指向具体元素的修改指令，如"tab 选中态颜色加深""卡片从正方形改长方形""去掉该图标"。AI 一轮即可落地。

前提：存在可视化产物作为共同语境——双方能指着同一个页面说话。没有共同语境时，先产出低保真原型（见 §7），再给元素级指令。

### 1.4 设计判断（把控品质）

对关键设计点给出**明确的判断与理由**，而不只是"好/不好/感觉不对"。好的设计判断包含立场和论据，例如：

- "不要用文案引导用户'他们和你一样'——共鸣应落在内容上，文案引导太刻意"（立场 + 理由）；
- "进阶内容不应该展示在首屏，应该在内页——你觉得呢？"（立场 + 保留 AI 的独立判断空间）。

### 1.5 元规则（沉淀为长期约束）

过程中确立的、对后续所有产物都成立的规则。元规则一旦确立就写入检查清单，不再逐轮重复（见 §5）。

## 2. 通道效率对比与三个"尽早"

首个案例（约 70 轮原型打磨）的观察：

| 通道 | 单轮收敛概率 | 适用阶段 |
|---|---|---|
| 参照物输入 | 高 | 方向确立、视觉打磨前 |
| 元素级指令 | 高 | 视觉打磨期 |
| 设计判断 | 中高 | 全程 |
| 概念锚点 | 中 | 方向确立期 |
| 方向性整体反馈（"感觉不对"） | 低，需 2-3 轮拆解 | 早期探索 |

关键观察：**约半数迭代轮次发生在参照物与真实数据就位之前**。由此得出三个"尽早"：

1. **尽早给参照物**——开工前收集，不要等 AI 自己猜；
2. **尽早可视化**——文字讨论到抽象极限就切换原型，不要在文字上空转；
3. **尽早换真实数据**——占位内容支撑不了密度、长度、信息分级的判断。

按此执行，迭代轮次可望显著压缩（首案例估计可压缩一半以上，待校准）。

## 3. 参照物清单模板

方案探索或原型任务开工前，向需求方收集并登记：

```markdown
## 参照物清单

| 参照物 | 形式 | 传递的诉求 | 到位时间 |
|---|---|---|---|
| 例：某参照产品的规划方案 | 文档链接 | 规划文档的结构与写法 | 已到位 |
| 例：真实功能截图 | 截图 N 张 | 功能的真实形态与分类方式 | 已到位 |
| 例：内容台账 | 表格 | 全部内容的真实约束（数量、结构、字段） | 已到位 |
| 例：目标拆解与经营数据 | 文档 | 目标的数字口径 | 已到位 |
```

登记要求：每项必须写明"传递的诉求"——只给材料不给诉求，AI 仍需猜测取哪些部分。清单随需求定义或原型任务交接，缺失项标注"建议补齐"及预计增加的迭代成本。

## 4. 文案负面清单（四条红线）

用户可见文案的四条红线，命中即改，适用于一切产出用户可见内容的产物（原型、PRD 内容契约、交付文档）：

1. **性别指代**：不出现"她/他"等性别指代，用"大家""同学"等包容性表述；
2. **内部口径外泄**：排序逻辑、运营策略、未完成能力等内部实现信息不写给用户看（反例："没读过的排在前面"——排序逻辑是实现，不是对用户说的话）；
3. **营销感与紧迫感**：不过度营销、不制造紧迫感，引导只保留用户主动触发的形态（反例："想更系统地学"营销感过重）；
4. **弃案与内部讨论**：用户可见内容与正式文档不解释弃案、不暴露内部讨论过程（反例："和你一样的人，在这里的日子"——用文案替用户下结论，共鸣应落在内容本身）。

## 5. 元规则（长期约束）

1. 文档只写事实与结论，不写内部讨论、不解释弃案；
2. 用户可见文案不出现内部口径；
3. 不过度营销、不制造紧迫感；
4. 文案与视觉避免性别指代；
5. AI 应从论据出发独立推断，不因为"是需求方说的"就直接照做；需求方也应主动保留 AI 的独立判断空间（"你分析看看，不必完全听从我"）。

第 5 条是双向的：需求方把话说成"参考"而不是"指令"，AI 把指令还原为"论据"再推断——两者共同避免"需求方定调、AI 照做"的假共识。

## 6. 调性类诉求的传递法

"温暖""高级""有品质""展览感"这类审美诉求**无法被规范文本完整传递**，不要指望写一段描述就让 AI 一次做对。有效模式是三段回路：

1. **调性输入（给标准不给色号）**：需求方给出审美标准与方向，如"吸引人逛下去的、漂亮点、看起来有品质的、温暖的、高级的"；
2. **专项技能审美翻译**：由环境中的 UI 设计专项技能（如 design-taste / frontend-design 或等价能力）把抽象调性翻译为排版、配色、组件的具体决策——专项能力短板用专项技能补齐，不靠原流程反复试错；
3. **元素级微调**：需求方在可视化产物上用元素级指令（通道 1.3）逐轮收敛。

需要保留人工闭环：审美判断本身由需求方负责，技能负责翻译与放大，不替代判断。

## 7. 低保真试错技巧

当文字方案的讨论触及抽象极限（"看不懂你想表达什么"），立即切换为单文件 HTML 快速原型承载讨论：

- 定位是**方向排除工具**，不是交付物——价值在于用最低成本排除错误布局与错误概念；
- 快速迭代、不打磨视觉，哪些方向信息过载、哪些概念只停留在文案层，指着页面说；
- 方向收敛即停，不恋战；进入高保真生产时换正式工程，不在试错稿上继续堆。

试错稿可以废弃，但其中确认的"布局可行性""概念是否落到设计层"等结论必须记录下来，随方向结论交接。
