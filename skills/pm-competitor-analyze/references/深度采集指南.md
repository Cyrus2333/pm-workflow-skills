# 竞品深度采集指南

用于对象多、来源长、需要联网深挖、需要长期留档或任务可能跨上下文执行的竞品分析。普通快速分析不必创建完整目录，但证据规则不变。

## 目录

1. 启用条件
2. 工作目录
3. 采集顺序
4. 单来源摘要
5. 合并底稿
6. 缺口与停止条件
7. 可视化选择
8. 完成检查

## 1. 启用条件

满足任一条件时建议启用：

- 分析 3 个以上对象，且每个对象需要读取多个来源
- 需要核对价格、规则、版本、地区、付费层级或历史变化
- 需要读取帮助中心、白皮书、PDF、发布记录或实际操作材料
- 预计无法在一次上下文中完成
- 报告需要由其他人复核或后续更新

不因“想写得全面”自动启用。若一个官方页面和一次实际体验已足以回答决策问题，直接维护证据台账即可。

## 2. 工作目录

在用户指定位置或当前项目合适的研究目录中建立：

```text
{主题}-竞品资料/
├── raw/          # 原始页面、文档、截图说明和操作记录
├── notes/        # 每个来源一份结构化摘要
├── merged.md     # 按决策维度合并的研究底稿
└── gaps.md       # 证据缺口、冲突和无法访问项
```

目录是临时研究产物还是项目正式资料，应在开始时说明。不要把抓取产物默认提交到产品代码仓库。

文件名使用稳定编号和可识别对象，例如 `A01-产品A-价格页-2026-08-05.md`。二进制文件保留原扩展名，并在对应摘要中记录转换方式。

## 3. 采集顺序

按“最接近产品事实的来源优先、根据缺口逐层扩展”执行：

1. 实际产品体验：入口、主流程、状态、权限、异常和反馈。
2. 官方产品资料：帮助中心、规则、价格、服务范围、版本和发布记录。
3. 官方公司资料：定位、客户案例、合作伙伴、合规与组织能力。
4. 可信第三方：行业数据、监管材料、公开采访和研究报告。
5. 用户评价：只用于发现体验线索和反例，不直接证明产品规则或总体效果。

先建立官方站点和文档的来源地图，再针对决策问题逐页读取。不要先进行无边界搜索，也不要为了完整性下载与决策无关的材料。

发现新的重要对象时，记录其可能价值；只有它会改变当前比较结论时才加入正式范围，并说明原因。

## 4. 单来源摘要

每个来源在 `notes/` 中形成一份摘要：

```markdown
# 来源摘要：{对象} / {页面或文档}

- 来源 URL / 文件：
- 发布或更新日期：
- 观察日期：
- 地区 / 端 / 版本 / 账号 / 付费层级：
- 来源类型：实际体验 / 官方说明 / 公开数据 / 用户评价
- 与决策问题的关系：

## 事实摘录

| 编号 | 事实观察 | 原文位置 / 操作步骤 | 可证明什么 | 不能证明什么 |
|---|---|---|---|---|

## 分析备注

- 推断：
- 待验证假设：
- 与其他来源的冲突：
- 后续需要补证据：
```

事实摘录保留足以复核的上下文，不整页复制。摘要中必须把来源原意和分析者推断分开。

## 5. 合并底稿

`merged.md` 不是原始摘要拼接，而是按决策问题重新组织：

1. 决策问题、范围、模式和深度
2. 对象、版本与体验条件
3. 统一任务或单品机制问题
4. 按决策维度整理的事实
5. 来源冲突、时效差异和证据强弱
6. 共性机制、关键差异及可能原因
7. 当前产品约束与适用性
8. 尚未解决的证据缺口

每条关键事实使用来源编号回链到 `notes/`。最终报告优先读取 `merged.md`，需要复核时再回到摘要和原始材料，避免依赖上下文残留。

## 6. 缺口与停止条件

在 `gaps.md` 中记录：无法登录的功能、未公开数据、互相冲突的来源、可能过期的信息和待确认的当前产品事实。

满足以下条件即可停止采集：

- 核心决策问题已有至少一条直接证据或被明确标为无法验证
- 关键差异能回溯到来源和体验条件
- 新增来源只重复既有信息，不再改变结论或可信度
- 剩余缺口已说明会不会影响建议

不要把“搜不到”转换成估算值，也不要持续搜索到所有模板栏目都有内容。

## 7. 可视化选择

| 要表达的关系 | 优先形式 | 使用条件 |
|---|---|---|
| 用户完成任务的步骤和分支 | 流程图 | 文字难以清楚表达顺序和分支 |
| 多角色或多系统交互 | 时序图 | 调用顺序和失败反馈影响判断 |
| 状态及允许动作 | 状态图 / 状态表 | 状态转换是关键差异 |
| 对象在两个维度的位置 | 定位图 | 坐标轴有明确定义和证据 |
| 多维事实比较 | 对比表 | 各维度口径一致 |

没有可靠评分尺度时不制作雷达图、星级榜单或综合分。图后用完整句子解释其决策意义，正文不得依赖图表才能成立。

## 8. 完成检查

- [ ] 原始来源、摘要和合并底稿能够逐级回溯
- [ ] 来源日期、观察日期和体验条件已记录
- [ ] 事实、用户评价、推断和假设没有混写
- [ ] 合并底稿围绕决策维度，而不是按网页顺序堆叠
- [ ] 未公开、无法体验和冲突信息已进入缺口记录
- [ ] 已达到停止条件，没有为了填框架继续无边界采集
- [ ] 图表有证据、有解释，并可被正文替代
