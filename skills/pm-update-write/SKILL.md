# pm-update-write

把已确认变化转换成便于知晓、执行或追踪的更新材料。

本 skill 只转换和传播已确认事实，不负责补做需求定义、改变产品方向或替代 PRD；输入存在冲突时先返回对应决策或交付文档确认。

## 优先读取

1. [更新说明模板](./references/更新说明模板.md)
2. 已确认的 PRD、决策记录、版本计划或上线结论
3. 与目标受众相关的规则、运营和执行文档

## 选择输出类型

### 更新说明

用于解释为什么更新、改了什么、影响谁、何时生效以及需要做什么。

### 变更通知

用于原计划、范围、规则或时间发生变化时，明确新旧差异、原因和行动项。

### 更新日志

用于按版本或日期记录新增、调整、修复、下线和已知限制。面向用户时避免技术提交语言；面向内部时可补充影响模块和负责人。

## 工作流程

1. 明确同步目的：知情、确认、决策、执行或留档。
2. 确认受众及其最关心的目标、操作、风险和时间。
3. 从已确认材料中提取背景、变化、不变项、影响和证据。
4. 将未确认项与既定结论分开，不擅自补全。
5. 明确生效范围、时间、负责人、截止时间和资料入口。
6. 按输出类型控制篇幅和表达，不照搬整份 PRD。

## 默认输出

1. 标题与一句话结论
2. 更新背景与目标
3. 新增、调整、修复、下线或计划变化
4. 明确不变项
5. 影响范围、生效时间和兼容说明
6. 需要相关方执行或确认的事项
7. 风险、已知限制和待确认项
8. 相关资料、负责人和反馈入口

## 完成标准

- 标题和开头能直接看出更新内容与目的
- 新旧差异、影响对象和生效时间无歧义
- 行动项包含负责人、结果和时间
- 已知限制与未确认信息明确标记
- 更新日志按统一分类和时间顺序组织
- 文案符合目标受众，不使用无必要的技术术语
