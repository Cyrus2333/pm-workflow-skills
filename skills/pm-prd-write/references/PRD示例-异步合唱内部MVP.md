# PRD 示例：异步合唱内部 MVP

> 虚构化示例，基于一次“单页 + 多信息区 + 异步任务”的内部 MVP 协作反馈整理。用于展示：PRD 与研发 spec 边界、评审简版、单页多模块表达、自动重合成规则和 spec 交接清单。业务规则、歌曲素材、路径和技术方案不可直接用于真实项目。

## 本示例重点

- **输出形态：**内部 MVP 组合，包含评审简版、标准 PRD 和研发 spec 交接清单。
- **页面表达：**1 个 H5 页面，页面内 6 个信息区；不是 6 个独立页面。
- **PRD 粒度：**写清产品能力、页面状态、业务规则和验收；不写 API 路径、请求 / 响应字段、错误码、队列、存储路径或混音算法。
- **适用场景：**内部体验、微信 H5 优先、异步合成任务、投稿新增 / 删除会触发系统重新生成最新作品。

## 评审简版

### 一句话方案

为业务同事提供一个微信 H5 优先的异步合唱内部 MVP：用户进入固定歌曲活动页后，可试听原唱、录制并提交自己的声音；系统在新增、替换或删除有效投稿后自动重新合成最新合唱作品，页面展示原唱、最新作品、投稿池和合成状态，用于验证“多人异步参与后生成合唱作品”的核心体验是否成立。

### 目标与非目标

| 类型 | 内容 |
|---|---|
| 目标 | 验证业务同事能否在微信 H5 内顺利完成录音、提交、自动合成和播放最新作品的闭环。 |
| 目标 | 验证合唱成品是否达到“能听出多人一起唱，并具备趣味性”的最低内部体验标准。 |
| 非目标 | 不做实时连麦、不做视频、不做多歌曲后台、不做公开传播、不做评论点赞排行、不做专业修音。 |

### 体验结构

本期只有 **PAGE-01 异步合唱活动页**。页面内包含 6 个信息区：

1. 活动与玩法说明区；
2. 原唱播放器区；
3. 最新合唱作品区；
4. 录音与试听区；
5. 投稿池区；
6. 合成状态与提示区。

主链路：进入页面 → 播放原唱 → 开始录音 → 停止录音 → 试听 → 提交 → 系统自动合成 → 播放最新合唱作品。

删除链路：用户删除自己的有效投稿 → 投稿池更新 → 系统自动重新合成 → 最新作品更新；若合成失败，页面保留上一版可播放作品并提示失败。

### 核心规则

| 规则 | 结论 |
|---|---|
| 投稿有效性 | 单个用户默认只保留 1 条有效投稿；再次提交视为替换最新有效投稿。 |
| 删除权限 | 用户只能删除自己的有效投稿；他人投稿不展示删除入口，系统也必须拦截。 |
| 自动合成 | 新增、替换或删除有效投稿后均自动触发重新合成，用户不需要点击“合成”按钮。 |
| 失败兜底 | 合成失败时不误展示为成功；如存在上一版成功作品，继续保留可播放入口。 |

### MVP 验收底线

- 至少 2 名业务同事能在微信 H5 中完成录音、提交和播放最新作品。
- 新增或替换投稿后，页面进入合成中状态，合成成功后最新作品更新。
- 删除自己的投稿后，最新作品不再包含该投稿，并在合成完成后更新。
- 微信录音不可用、提交失败、合成失败时均有明确提示，不进入假成功状态。

### 待研发 spec 补齐

- 微信录音授权、素材获取、上传和服务端处理链路。
- 录音素材存储、转码、混音、任务队列、重试超时和失败告警方案。
- 页面所需活动详情、投稿提交、投稿删除、合成状态查询等能力的接口规格。
- 内部体验数据、日志和排查方式。

### 1.1 问题、目标与成功假设

| 问题与证据摘要 | 目标 ID / 目标状态 | 目标人群与场景 | 方向级成功假设 |
|---|---|---|---|

## 2. 方案总览、体验结构与原型

### 2.1 方案闭环与目标流程

用户在一个页面内完成参与：先听原唱，再录制并试听自己的声音；提交成功后，投稿池立即体现自己的有效投稿，系统自动进入合成中；合成成功后，最新作品播放器更新为新版本。删除自己的投稿后，系统按剩余有效投稿重新生成最新作品。

| 场景 ID | 阶段 / 时间点 | 角色 / 系统 | 前置输入 | 动作 | 系统反馈 | 下一步 / 临界点 |
|---|---|---|---|---|---|---|
| SCN-01 | 进入活动 | 用户 / 页面 | 活动链接可访问 | 用户打开 H5 页面 | 页面展示活动说明、原唱、最新作品状态、投稿池和录音入口 | 活动加载失败时展示重试 |
| SCN-01 | 录音前 | 用户 | 原唱可播放，微信录音能力可用 | 用户播放原唱并点击开始录音 | 页面进入录音中，提示正在录制 | 微信录音不可用时阻止进入假录音状态 |
| SCN-01 | 录音后 | 用户 | 已停止录音 | 用户试听自己的录音 | 页面可播放本次录音，展示重录和提交入口 | 用户可重录或提交 |
| SCN-01 | 提交后 | 系统 | 用户确认提交 | 保存或替换用户有效投稿，并触发自动合成 | 页面展示提交成功、投稿池更新和合成中 | 合成成功后更新最新作品；失败时提示 |
| SCN-02 | 删除投稿 | 用户 / 系统 | 用户已有有效投稿 | 用户删除自己的投稿 | 投稿池移除该投稿，触发自动重新合成 | 合成成功后最新作品不再包含该投稿 |

本需求没有跨页面跳转，主路径发生在 **PAGE-01 单页内**。页面 / 状态转移列描述的是同一页面内的信息区状态变化。

| 动线 ID | 场景 ID | 入口 / 起点 | 用户目的与关键动作 | 页面 / 状态转移 | 关键分支 | 结果 / 出口 | 返回、失败、取消或重试 |
|---|---|---|---|---|---|---|---|
| FLOW-01 | SCN-01 | PAGE-01 活动页 | 听原唱、录音、试听并提交 | 未录制 → 录音中 → 待试听 → 提交中 → 已提交 / 合成中 → 最新作品可播放 | 微信录音不可用、提交失败、合成失败 | 用户听到最新合唱作品 | 提交失败保留本地试听结果；合成失败保留上一版作品 |
| FLOW-02 | SCN-02 | PAGE-01 投稿池区 | 删除自己的投稿 | 已提交 → 删除确认 → 投稿池更新 / 合成中 | 只能删除自己的投稿；重复删除不造成错误结果 | 最新作品基于剩余投稿生成 | 删除失败保留投稿并提示重试 |

#### FR-01 页面加载活动信息

**需求结论**

用户进入 PAGE-01 后，页面应加载并展示活动基础信息、原唱可用状态、最新合唱作品状态、当前有效投稿集合、当前用户投稿状态和合成状态。加载成功后，6 个信息区应形成一致的初始状态，让用户知道当前能否听原唱、是否已有最新作品、能否录音提交、自己是否已有投稿。加载失败或关键数据缺失时，页面必须明确提示并提供重试，不得让用户在信息不完整时误以为可以完成提交或播放。

**行为说明**

1. **触发与前提：**用户通过内部 H5 链接进入 PAGE-01，页面开始获取当前活动所需的产品数据。活动必须处于可访问状态；若活动已关闭、不可访问或数据不存在，页面进入对应终止态，不展示录音提交主操作。
2. **用户可见行为：**加载中展示页面级加载反馈，不提前展示可点击的录音、提交或删除入口。加载成功后，IA-01 至 IA-06 同步更新：活动说明可读、原唱播放器按素材状态展示、最新作品按合成状态展示、录音区按用户状态展示、投稿池展示有效投稿、合成提示区展示当前任务状态。
3. **系统与数据行为：**系统需要向页面提供足以判断上述信息区状态的活动、投稿和合成结果。PRD 不规定接口字段、缓存策略或错误码；研发 spec 需保证页面能得到唯一且一致的渲染状态。
4. **结果与后续路径：**加载成功且活动允许投稿时，用户可继续播放原唱和录音。加载失败时，用户只能重试或退出；重试成功后重新进入正常页面状态。

**条件与分支**

| 进入条件 | 用户看到什么 | 可执行操作 | 系统处理与数据结果 | 后续页面 / 状态 | 优先级或冲突规则 |
|---|---|---|---|---|---|
| 活动加载中 | 页面骨架或加载提示，录音和提交入口不可用 | 等待或退出 | 不产生投稿、删除或合成副作用 | 加载成功 / 加载失败 | 加载中不得展示旧的可操作状态 |
| 活动加载成功，允许内部体验 | 6 个信息区按当前活动、投稿和合成状态展示 | 播放原唱、录音、查看投稿、播放最新作品（如有） | 页面获得当前渲染状态 | PAGE-01 可操作 | 以最新加载结果为准 |
| 活动不存在或已关闭 | 活动不可用提示，说明暂不能参与 | 返回或退出 | 不允许录音、提交、删除 | 终止态 | 高于所有录音和投稿状态 |
| 关键数据部分缺失，如缺少原唱可用状态或投稿状态 | 页面说明活动信息暂不完整，关键操作不可用 | 重新加载 | 不写入投稿，不触发合成 | 重试后重新判断 | 数据不完整时不得进入半成功状态 |
| 网络或服务异常导致加载失败 | 页面级错误提示和“重新加载”入口 | 点击重新加载 | 重新获取活动渲染状态 | 加载中 / 加载成功 / 加载失败 | 不复用可能过期的操作状态 |

**异常与恢复**

| 异常条件 | 用户反馈 | 系统 / 数据处理 | 是否可重试及方式 | 记录与告警 |
|---|---|---|---|---|
| 页面初始加载失败 | “活动信息加载失败，请重试” | 不产生任何投稿、删除和合成结果 | 可点击重新加载 | 记录页面加载失败，具体日志由 spec 定义 |
| 活动状态在页面停留期间变化 | 用户操作时看到状态刷新或操作失败原因 | 操作结果以系统最新判断为准 | 刷新页面状态后可继续 | 记录状态变化导致的操作失败 |
| 投稿或合成状态暂时不可用 | 投稿池或最新作品区展示暂不可用提示 | 不把未知状态当作空态或成功态 | 可刷新 | 记录状态缺失 |

- 本功能只定义页面进入后的产品渲染状态，不定义 API 路径、字段、缓存、鉴权和错误码。

- 固定歌曲和内部体验边界来自需求定义；本 PRD 不扩展为多歌曲或公开活动管理。

#### FR-02 原唱播放

**需求结论**

原唱播放器是用户录音前理解歌曲节奏和内容的基础能力，应在页面加载成功后稳定可见。用户可以播放、暂停和重播原唱；若原唱不可播放，用户不能继续录音提交，因为录音会失去参考。原唱播放规则需要与录音状态配合，避免用户在录音过程中因播放器状态混乱而无法判断自己正在唱什么。

**行为说明**

1. **触发与前提：**页面加载成功且固定原唱素材可用时，IA-02 展示原唱播放器。用户点击播放、暂停或重播时触发播放器状态变化。
2. **用户可见行为：**播放器至少展示歌曲名称、播放状态、播放 / 暂停入口和加载 / 失败提示。录音前用户可自由播放原唱；进入录音中后，页面应明确当前原唱是否继续播放，不能出现“看似播放但无声”或“录音已开始但原唱状态不明”的情况。
3. **系统与数据行为：**系统提供可播放原唱素材；页面管理原唱播放器与录音状态的产品交互关系。具体音频格式、CDN、缓存和播放器实现交给研发 spec。
4. **结果与后续路径：**原唱可播放时，用户可进入录音流程。原唱失败时，页面提示无法继续录音，用户可重试加载或退出。

**条件与分支**

| 进入条件 | 用户看到什么 | 可执行操作 | 系统处理与数据结果 | 后续页面 / 状态 | 优先级或冲突规则 |
|---|---|---|---|---|---|
| 原唱未播放 | 播放按钮可用，显示歌曲名称 | 播放原唱 | 播放器进入播放中 | 原唱播放中 | 默认状态 |
| 原唱播放中 | 暂停入口和播放进度 | 暂停 / 重播；进入录音前可继续试听 | 播放器状态更新 | 暂停 / 重播 / 准备录音 | 录音规则高于播放自由度 |
| 用户点击开始录音 | 页面提示录音即将开始，原唱播放关系明确 | 确认开始或取消 | 按产品规则处理原唱播放，页面进入录音中 | 录音中 | 不能同时出现冲突按钮状态 |
| 原唱加载失败 | 原唱区显示失败提示，录音入口不可用或明确禁用原因 | 重试加载原唱 | 不进入录音中，不产生投稿 | 原唱可用 / 原唱失败 | 原唱失败阻塞录音主链路 |

**异常与恢复**

| 异常条件 | 用户反馈 | 系统 / 数据处理 | 是否可重试及方式 | 记录与告警 |
|---|---|---|---|---|
| 原唱播放中断 | 提示“原唱播放失败，请重试” | 保持未提交录音不受影响 | 可重试播放 | 记录播放器失败 |
| 录音前原唱不可用 | 提示“原唱暂不可播放，无法开始录音” | 不进入录音状态 | 可重新加载页面或重试播放器 | 记录素材不可用 |
| 用户在录音中尝试操作原唱 | 按既定录音中规则展示禁用或明确说明 | 不影响当前录音状态 | 停止录音后恢复操作 | 不需要业务告警 |

**保持不变与边界**

- 本功能不定义音频格式、音量处理、缓存、CDN 或底层播放器技术。
- 本期固定一首歌，不提供切歌、收藏、下载或分享能力。
- 原唱失败会阻塞录音，但不阻塞用户查看投稿池或已有最新作品。

**追溯**

- 对应目标 / 场景：OBJ-01 / SCN-01。
- 所属页面 / 信息结构：PAGE-01 / IA-02。
- 关联规则：RULE-04。
- 对应验收：AC-01、AC-03。

#### FR-03 最新合唱作品播放

**需求结论**

最新合唱作品区让用户感知“大家的声音已经被合成到一起”，是 MVP 体验判断的核心结果区。页面应根据作品状态展示无作品、合成中、合成成功和合成失败，不得把失败或过期结果伪装为最新成功作品。合成失败时，如果存在上一版成功作品，用户仍可播放上一版，但页面必须说明最新版本生成失败。

**行为说明**

1. **触发与前提：**页面加载成功后，IA-03 根据当前合成作品状态展示；每次投稿新增、替换或删除后，该区域随合成状态更新。
2. **用户可见行为：**无作品时展示空态；合成中时展示生成中提示；成功时展示可播放作品；失败时展示失败提示，并根据是否有上一版成功作品决定是否保留播放器。
3. **系统与数据行为：**系统提供当前最新成功作品和当前合成任务的产品状态。PRD 不规定文件地址字段、版本号字段或轮询机制；spec 需保证页面能识别“当前最新成功作品”和“本轮合成状态”。
4. **结果与后续路径：**用户能播放最新成功作品，或理解为什么暂时没有可播放作品。后续投稿变化会再次进入合成中并最终更新该区域。

**条件与分支**

| 进入条件 | 用户看到什么 | 可执行操作 | 系统处理与数据结果 | 后续页面 / 状态 | 优先级或冲突规则 |
|---|---|---|---|---|---|
| 当前无有效投稿，且无历史成功作品 | 最新作品区展示暂无作品 | 无播放操作 | 不触发合成 | 等待用户提交投稿 | 无投稿空态不是错误 |
| 有投稿变化，本轮正在合成 | 展示“正在生成最新版本”；如有上一版，可继续播放上一版并标明不是最新 | 播放上一版（如有）、等待或刷新 | 合成任务继续处理 | 成功 / 失败 | 合成中状态高于静态成功展示 |
| 本轮合成成功 | 展示最新作品播放器和成功状态 | 播放 / 暂停 / 重播最新作品 | 最新成功作品成为页面默认播放对象 | 等待后续投稿变化 | 成功结果覆盖上一版 |
| 本轮合成失败且有上一版成功作品 | 展示失败提示，同时保留上一版播放器 | 播放上一版 | 不把失败结果设为最新成功作品 | 后续投稿变化后可再次合成 | 必须说明上一版不是本轮最新结果 |
| 本轮合成失败且无上一版作品 | 展示生成失败，暂无可播放作品 | 无播放操作，可等待后续重新触发 | 不生成假作品 | 后续投稿变化后可再次合成 | 失败不得展示为成功 |

**异常与恢复**

| 异常条件 | 用户反馈 | 系统 / 数据处理 | 是否可重试及方式 | 记录与告警 |
|---|---|---|---|---|
| 最新作品播放失败 | 提示“作品播放失败，请稍后重试” | 不改变合成成功状态 | 可重试播放或刷新页面 | 记录播放失败 |
| 合成状态未知 | 展示“最新作品状态暂不可用” | 不覆盖上一版成功作品 | 可刷新 | 记录状态缺失 |
| 合成中等待较久 | 展示仍在生成中或稍后再听提示 | 不催生重复提交 | 用户可离开后再回来 | 记录长时间合成，告警细节由 spec 定义 |

**保持不变与边界**

- 本功能不定义作品文件命名、存储路径、音频格式和合成算法。
- 页面默认只展示最新成功作品；历史作品是否在后台保留只作为排查能力交给 spec。
- 本期不提供下载、分享、评论、点赞或排行。

**追溯**

- 对应目标 / 场景：OBJ-01、OBJ-03 / SCN-01、SCN-02。
- 所属页面 / 信息结构：PAGE-01 / IA-03、IA-06。
- 关联规则：RULE-04、RULE-05、RULE-06。
- 对应验收：AC-04、AC-05。

#### FR-04 微信录音、试听与重录

**需求结论**

微信录音是 MVP 的主链路。用户点击开始录音后，页面应清楚进入录音中状态；停止后，用户必须能试听本次录音，并可选择重录或提交。授权失败、录音失败或上传失败时，页面应给出明确提示并回到可理解状态，不得展示待试听、已提交或合成中等假成功状态。

**行为说明**

1. **触发与前提：**用户位于 IA-04，活动允许投稿，原唱可用，且当前不处于提交中、删除中或页面加载失败状态。用户点击开始录音触发录音流程。
2. **用户可见行为：**开始后按钮切换为录音中和停止入口，其他可能导致状态冲突的操作应禁用或明确提示。停止录音后，页面展示试听播放器、重录按钮和提交按钮；重录前应让用户理解会丢弃当前未提交录音。
3. **系统与数据行为：**系统需要获得一段可用于提交的本次录音素材。PRD 不定义微信 `serverId`、上传流程、转码格式或临时文件处理；spec 需保证产品上能区分“未录制、录音中、待试听、录音失败”。
4. **结果与后续路径：**用户满意后进入 FR-05 提交流程；不满意则重录并回到未录制 / 录音中。未提交录音不影响已提交有效投稿。

**条件与分支**

| 进入条件 | 用户看到什么 | 可执行操作 | 系统处理与数据结果 | 后续页面 / 状态 | 优先级或冲突规则 |
|---|---|---|---|---|---|
| 未录制且可录音 | “开始录音”主按钮可用，提示建议先听原唱 | 开始录音 | 准备录音能力 | 录音中 / 录音失败 | 活动关闭或原唱失败时禁用 |
| 录音中 | 录音中提示、停止录音入口，提交不可用 | 停止录音 | 生成本次待试听录音 | 待试听 / 录音失败 | 录音中不得重复开始录音 |
| 待试听 | 本次录音试听、重录、提交入口 | 试听 / 重录 / 提交 | 试听不产生投稿；重录丢弃本次未提交录音 | 待试听 / 未录制 / 提交中 | 重录不影响已提交投稿 |
| 微信授权失败或录音能力不可用 | 明确提示无法录音 | 重试授权 / 返回 / 刷新 | 不生成待提交录音 | 未录制 / 录音失败 | 不进入假录音状态 |
| 非微信环境访问 | 提示当前优先支持微信 H5，按产品确认展示兜底 | 查看说明；如有兜底则使用兜底 | 不默认承诺完整录音体验 | 兜底态 | 微信主链路优先 |

**异常与恢复**

| 异常条件 | 用户反馈 | 系统 / 数据处理 | 是否可重试及方式 | 记录与告警 |
|---|---|---|---|---|
| 用户拒绝录音授权 | 提示需要授权后才能录音 | 不创建录音 | 可重新授权或刷新 | 记录授权失败 |
| 录音中断或停止失败 | 提示录音失败，请重新录制 | 丢弃不完整录音 | 可重新开始录音 | 记录录音失败 |
| 试听播放失败 | 提示试听失败，建议重录 | 不提交不可确认录音 | 可重试试听或重录 | 记录试听失败 |
| 用户刷新或离开页面 | 未提交录音可能丢失，页面不承诺保留 | 不影响已提交有效投稿 | 返回后重新录音 | 不需要业务告警 |

**保持不变与边界**

- 未提交录音是本地或临时状态，不等同于有效投稿。
- 重录只丢弃当前未提交录音，不删除已提交投稿。
- 本功能不定义微信素材下载、音频转码、降噪、音量归一和混音处理。

**追溯**

- 对应目标 / 场景：OBJ-02 / SCN-01。
- 所属页面 / 信息结构：PAGE-01 / IA-04。
- 关联规则：不适用；受活动可投稿状态约束。
- 对应验收：AC-01、AC-03。

#### FR-05 提交或替换投稿

**需求结论**

用户在待试听状态下点击提交后，系统应把本次录音保存为该用户在当前活动下的唯一有效投稿；如果此前已有有效投稿，本次提交替换旧投稿。提交成功后，投稿池应立即体现“我的投稿”，最新作品区进入合成中；提交失败时保留本次待试听录音并允许重试，不得展示已提交或合成中成功路径。

**行为说明**

1. **触发与前提：**用户已完成录音并处于待试听状态，活动允许投稿，页面没有正在提交的请求。用户点击提交触发提交流程。
2. **用户可见行为：**点击后提交按钮进入加载态并禁止重复点击；页面保留当前录音试听结果，但避免用户在提交中重复重录造成状态混乱。提交成功时展示成功反馈，投稿池出现或更新“我的投稿”，合成状态进入合成中。
3. **系统与数据行为：**系统将本次录音变成当前用户的有效投稿；若已有有效投稿，则旧投稿不再有效且不参与下一版作品。具体提交接口、幂等键、存储路径和事务实现交给研发 spec。
4. **结果与后续路径：**提交成功后进入 FR-07 自动合成链路；提交失败时回到待试听状态，用户可以重试提交或重录。

**条件与分支**

| 进入条件 | 用户看到什么 | 可执行操作 | 系统处理与数据结果 | 后续页面 / 状态 | 优先级或冲突规则 |
|---|---|---|---|---|---|
| 首次提交，用户无有效投稿 | 提交按钮可用 | 点击提交 | 本次录音成为有效投稿 | 已提交 / 合成中 | 提交成功后触发合成 |
| 再次提交，用户已有有效投稿 | 提示或默认说明将以最新录音为准 | 点击提交 | 旧投稿失效，新录音成为唯一有效投稿 | 投稿池更新 / 合成中 | 单用户只保留一条有效投稿 |
| 提交中 | 提交按钮加载中，重复点击不可用 | 等待 | 不重复创建有效投稿 | 成功 / 失败 | 防重复优先级高 |
| 提交成功 | 成功提示，投稿池展示“我的投稿” | 可继续查看、播放作品、后续重录再提交 | 有效投稿集合变化，触发合成 | 合成中 | 投稿池和合成状态必须同步更新 |
| 提交失败 | 失败提示，本次试听保留，提交按钮恢复 | 重试提交 / 重录 | 不新增有效投稿，不触发合成成功态 | 待试听 | 失败不得覆盖旧有效投稿，除非系统已确认替换成功 |
| 活动在提交时变为不可投稿 | 展示不可投稿原因 | 返回页面或刷新 | 不保存为有效投稿 | 活动不可用 / 不可投稿 | 最新活动状态高于页面旧状态 |

**异常与恢复**

| 异常条件 | 用户反馈 | 系统 / 数据处理 | 是否可重试及方式 | 记录与告警 |
|---|---|---|---|---|
| 网络失败，结果未知 | 提示提交结果暂未确认，建议刷新查看投稿池 | 不在未确认时展示已提交 | 可刷新页面或重试；重复处理规则由 spec 保证 | 记录结果未知 |
| 提交被业务规则拒绝 | 展示可理解原因，如活动已关闭 | 不创建有效投稿 | 按原因决定是否可重试 | 记录业务失败 |
| 重复点击提交 | 按钮加载中，不产生第二次可见提交 | 不生成多个有效投稿 | 等待当前结果 | 记录可选，具体由 spec 定义 |

**保持不变与边界**

- 提交成功才算有效投稿；录音完成或试听完成都不算投稿。
- 单用户一条有效投稿是产品规则，不规定数据库唯一索引或幂等实现。
- 提交或替换后自动合成是产品结果，不规定任务创建方式。

**追溯**

- 对应目标 / 场景：OBJ-01、OBJ-03 / SCN-01。
- 所属页面 / 信息结构：PAGE-01 / IA-04、IA-05、IA-06。
- 关联规则：RULE-01。
- 对应验收：AC-01、AC-02。

#### FR-06 投稿池展示与删除自己的投稿

**需求结论**

投稿池用于展示当前参与最新合唱的有效投稿集合，并让用户确认自己的声音是否已经参与。列表需要区分“我的投稿”和“其他同事投稿”；只有我的有效投稿展示删除入口。删除成功后，该投稿从有效投稿集合中移除，并触发重新合成；删除失败时，投稿仍保留，页面明确提示失败并允许重试。

**行为说明**

1. **触发与前提：**页面加载成功后展示投稿池；提交成功、删除成功或刷新页面时更新投稿池。用户已有有效投稿时，可对自己的投稿发起删除。
2. **用户可见行为：**无投稿时展示空态；有投稿时展示投稿列表和我的投稿标识。我的投稿展示删除入口，点击后建议出现确认提示，避免误删；他人投稿不展示删除入口。
3. **系统与数据行为：**删除成功意味着该投稿不再是有效投稿，且不参与下一版合唱。具体软删除字段、权限校验实现和重复删除处理交给研发 spec。
4. **结果与后续路径：**删除成功后投稿池更新，合成状态进入合成中；删除失败时列表保持不变，用户可重试。

**条件与分支**

| 进入条件 | 用户看到什么 | 可执行操作 | 系统处理与数据结果 | 后续页面 / 状态 | 优先级或冲突规则 |
|---|---|---|---|---|---|
| 当前无有效投稿 | 投稿池空态，提示还没有同事投稿 | 去录音 | 不改变投稿集合 | 等待提交 | 空态不是错误 |
| 有他人有效投稿，无我的投稿 | 展示他人投稿，无删除入口 | 播放最新作品（如有）、去录音 | 不允许删除他人投稿 | 可提交自己的投稿 | 权限规则高于页面展示 |
| 有我的有效投稿 | 展示“我的投稿”和删除入口 | 删除 / 重新录音提交 | 删除或替换会改变有效投稿集合 | 删除中 / 合成中 | 我的投稿最多一条有效 |
| 删除确认中 | 展示确认文案，说明删除后会重新生成最新作品 | 确认删除 / 取消 | 取消不改变投稿 | 删除中 / 已提交 | 避免误删 |
| 删除成功 | 我的投稿从列表移除，提示已删除，合成中 | 重新录音提交 | 投稿失效并触发重合成 | 合成中 | 删除后不得继续参与最新作品 |
| 删除失败 | 投稿仍保留，展示失败原因或重试提示 | 重试删除 / 取消 | 投稿仍为有效投稿 | 已提交 | 不进入已删除状态 |

**异常与恢复**

| 异常条件 | 用户反馈 | 系统 / 数据处理 | 是否可重试及方式 | 记录与告警 |
|---|---|---|---|---|
| 删除请求失败 | 提示删除失败，投稿仍保留 | 不改变有效投稿集合 | 可重试删除 | 记录删除失败 |
| 重复删除或投稿已失效 | 页面刷新后不再展示该投稿，或提示已删除 | 以最新有效投稿集合为准 | 可刷新 | 记录状态不一致 |
| 尝试删除他人投稿 | 页面不提供入口；若异常触发则提示无权限 | 不改变他人投稿 | 不可重试，除非身份变化 | 记录权限异常 |

**保持不变与边界**

- 删除是从有效投稿集合中移除，不定义物理删除、保留周期和审计实现。
- 本期不支持管理员删除、批量删除、举报、审核和恢复投稿。
- 投稿池展示用于内部体验，不提供公开头像墙、排行或社交互动。

**追溯**

- 对应目标 / 场景：OBJ-03 / SCN-02。
- 所属页面 / 信息结构：PAGE-01 / IA-05、IA-06。
- 关联规则：RULE-01、RULE-02、RULE-03。
- 对应验收：AC-02、AC-04。

#### FR-07 自动重新合成与状态展示

**需求结论**

新增有效投稿、替换有效投稿和删除有效投稿都会自动触发重新合成，用户不需要也不应该操作“合成”按钮。页面需要让用户理解当前最新作品是否正在生成、是否已成功、是否失败，以及当前可播放作品是否为上一版。多次投稿变化连续发生时，页面最终应呈现基于最新有效投稿集合的合唱结果；具体任务去重、排队和并发处理由研发 spec 定义。

**行为说明**

1. **触发与前提：**FR-05 提交 / 替换成功或 FR-06 删除成功后，系统进入自动合成链路。页面在 IA-06 展示合成状态，在 IA-03 展示最新作品区对应状态。
2. **用户可见行为：**合成中显示“正在生成最新版本”一类提示；成功后最新作品播放器更新；失败后显示失败提示。若合成中或失败时存在上一版成功作品，页面可保留播放入口，但必须标明它不是本轮最新结果。
3. **系统与数据行为：**系统基于当前有效投稿集合生成合唱作品。PRD 不规定队列、任务 ID、去重、重试、超时、文件存储或混音算法；spec 需保证产品上可识别当前作品状态和最新成功作品。
4. **结果与后续路径：**合成成功后用户可播放最新作品；失败时用户可继续查看投稿池、播放上一版作品（如有），并等待后续投稿变化再次触发合成。

**条件与分支**

| 进入条件 | 用户看到什么 | 可执行操作 | 系统处理与数据结果 | 后续页面 / 状态 | 优先级或冲突规则 |
|---|---|---|---|---|---|
| 首个有效投稿提交成功 | 最新作品区进入合成中，投稿池展示有效投稿 | 等待、播放原唱、查看投稿池 | 自动触发合成 | 成功 / 失败 | 有效投稿变化必须触发合成 |
| 用户替换有效投稿成功 | 提示正在基于最新投稿重新生成 | 可播放上一版作品（如有） | 旧投稿不参与新作品，新投稿参与 | 最新成功 / 失败 | 新投稿集合高于旧作品 |
| 用户删除有效投稿成功 | 提示正在重新生成最新作品 | 等待或重新投稿 | 被删除投稿不参与新作品 | 最新成功 / 失败 / 无作品 | 删除规则高于上一版内容 |
| 合成成功 | 最新作品播放器更新，合成提示消失或显示已更新 | 播放最新作品 | 最新成功作品更新 | 可播放 | 成功状态覆盖合成中 |
| 合成失败 | 展示失败提示；上一版如有则保留 | 播放上一版（如有）、继续投稿 | 不生成新的最新成功作品 | 失败态 | 失败不得覆盖上一版成功作品 |
| 连续多次投稿变化 | 页面提示正在生成最新版本 | 等待、查看投稿池 | 最终结果应对应最新有效投稿集合 | 最新成功 / 失败 | 产品结果以最新有效集合为准，技术实现交给 spec |

**异常与恢复**

| 异常条件 | 用户反馈 | 系统 / 数据处理 | 是否可重试及方式 | 记录与告警 |
|---|---|---|---|---|
| 合成长时间未完成 | 提示仍在生成，可稍后回来 | 不展示假成功 | 用户可刷新或稍后访问 | 记录长耗时，告警方案由 spec 定义 |
| 合成失败 | 提示最新版本生成失败 | 不更新最新成功作品 | 后续投稿变化可再次触发 | 记录合成失败 |
| 状态刷新失败 | 提示状态暂不可用，保留已知安全状态 | 不把未知状态当成功 | 可刷新页面 | 记录状态刷新失败 |

**保持不变与边界**

- 自动合成是产品触发规则，不定义任务队列和算法实现。
- 本期不提供用户手动合成按钮。
- 页面只要求展示最新成功作品；历史版本管理和排查入口由 spec 或后台方案决定。

**追溯**

- 对应目标 / 场景：OBJ-03 / SCN-01、SCN-02。
- 所属页面 / 信息结构：PAGE-01 / IA-03、IA-06。
- 关联规则：RULE-01、RULE-02、RULE-05、RULE-06。
- 对应验收：AC-02、AC-04、AC-05。

#### FR-08 空态和失败兜底

**需求结论**

MVP 可以接受部分能力失败，但不能让用户误解当前状态。页面需要覆盖无投稿、原唱失败、录音失败、提交失败、删除失败、合成失败和页面整体加载失败等关键分支，并明确哪些情况下用户可以继续、哪些情况下必须重试或退出。所有失败态都应优先保护用户理解和数据正确性，不为了流程顺畅展示假成功。

**行为说明**

1. **触发与前提：**任一关键能力无数据、失败或状态未知时触发对应兜底。兜底应发生在对应信息区，页面级失败才覆盖整页。
2. **用户可见行为：**用户能看到明确状态说明、可行下一步和不可操作原因。例如无投稿时鼓励录音，提交失败时保留试听，合成失败时说明最新作品未生成。
3. **系统与数据行为：**失败态不应产生错误的有效投稿、已删除、最新成功作品或公开传播结果。具体错误码、重试次数和告警通道交给研发 spec。
4. **结果与后续路径：**用户可以按提示重试、刷新、重新录音、稍后再看或退出；页面不要求用户理解底层技术原因。

**条件与分支**

| 进入条件 | 用户看到什么 | 可执行操作 | 系统处理与数据结果 | 后续页面 / 状态 | 优先级或冲突规则 |
|---|---|---|---|---|---|
| 无有效投稿 | 投稿池空态，最新作品暂无 | 开始录音 | 不触发合成，直到有投稿 | 待录音 / 提交后合成中 | 空态不算失败 |
| 原唱失败 | 原唱区失败提示，录音入口禁用或说明原因 | 重试原唱 / 刷新 | 不进入录音 | 原唱可用 / 失败 | 原唱失败阻塞录音 |
| 录音失败 | 录音区失败提示 | 重新录音 | 不生成待提交录音 | 未录制 | 不可提交失败录音 |
| 提交失败 | 提交失败提示，保留试听 | 重试提交 / 重录 | 不新增有效投稿 | 待试听 | 不触发合成成功态 |
| 删除失败 | 删除失败提示，投稿仍展示 | 重试删除 | 有效投稿保持不变 | 已提交 | 不触发删除后的合成成功态 |
| 合成失败 | 最新作品区失败提示；上一版如有保留 | 播放上一版 / 稍后查看 | 不更新最新成功作品 | 失败 / 后续合成中 | 不展示假最新作品 |
| 页面整体加载失败 | 整页错误和重试入口 | 重新加载 | 不产生业务副作用 | 加载中 / 成功 / 失败 | 页面级失败高于区块态 |

**异常与恢复**

| 异常条件 | 用户反馈 | 系统 / 数据处理 | 是否可重试及方式 | 记录与告警 |
|---|---|---|---|---|
| 多个区块同时失败 | 优先展示会阻塞主链路的失败，例如页面加载或原唱失败 | 各区块独立保持安全状态 | 按区块重试或整页刷新 | 记录组合失败 |
| 用户在失败态重复点击 | 按钮应禁用或提示当前不可操作 | 不产生重复副作用 | 恢复后可操作 | 记录异常点击可选 |
| 状态不一致 | 提示刷新后查看最新状态 | 以刷新后的系统状态为准 | 可刷新 | 记录状态不一致 |

**保持不变与边界**

- 兜底文案应让内部体验者知道下一步，不需要暴露技术错误细节。
- 本期不承诺大规模并发、高可用 SLA 或正式客服流程。
- 隐私和内部使用提示属于关键边界，失败态不得引导公开传播。

**追溯**

- 对应目标 / 场景：OBJ-01、OBJ-02、OBJ-03 / SCN-01、SCN-02。
- 所属页面 / 信息结构：PAGE-01 / IA-01 至 IA-06。
- 关联规则：RULE-04、RULE-05、RULE-06。
- 对应验收：AC-03、AC-05。

### 5.3 发布方案

- 上线前准备：确认内部体验名单、入口链接、素材使用范围和问题反馈渠道。
- 灰度范围：先对产品、研发和少量业务同事开放；确认主链路可用后扩大内部体验。
- 回滚条件：微信录音大面积不可用、提交后无法恢复、合成结果持续不可用或出现声音公开风险。
- 回滚方式：关闭入口或降级为只展示原唱和玩法说明；保留已提交素材用于排查时需遵守内部隐私约束。

### 6.2 研发验收标准

#### AC-01 用户能完成提交并看到自己的投稿

- **Given：**用户通过微信打开 PAGE-01，原唱可播放，录音能力可用，活动当前允许投稿。
- **When：**用户完成录音、试听并提交。
- **Then：**页面提示提交成功，投稿池展示“我的投稿”，系统进入合成中状态；提交失败时页面保留本次试听结果并允许重试，不展示已提交。

#### AC-02 再次提交会替换自己的有效投稿

- **Given：**用户已经有一条有效投稿。
- **When：**用户重新录音并再次提交成功。
- **Then：**投稿池中该用户仍只有一条有效投稿，内容以最新提交为准，并触发新一轮合成。

#### AC-03 微信录音不可用时不会假成功

- **Given：**微信授权失败、录音 API 不可用或上传失败。
- **When：**用户尝试录音或提交。
- **Then：**页面展示明确失败原因或重试提示，不展示待试听、已提交或合成中成功路径；原唱播放器仍按可用状态展示。

#### AC-04 删除自己的投稿后会重新合成

- **Given：**用户已有有效投稿，且投稿池中可能还有其他同事投稿。
- **When：**用户删除自己的投稿成功。
- **Then：**投稿池不再展示该投稿，该投稿不参与下一版合唱，页面进入合成中；合成成功后最新作品更新为不包含该投稿的版本。

#### AC-05 合成失败能够明确兜底

- **Given：**投稿变化后系统开始合成，且存在“有上一版作品”和“无上一版作品”两组数据。
- **When：**本轮合成失败。
- **Then：**页面提示最新版本生成失败；有上一版作品时继续允许播放上一版，无上一版作品时展示暂无可播放作品；页面不得把失败版本展示为成功。

## 7. 效果验证

内部 MVP 不设置对外增长指标，使用体验完成信号和护栏判断是否继续投入。

| 指标 ID | 对应目标 | 类型 | 定义与计算口径 | 基线 | 目标 / 阈值 | 数据来源 | 周期 | 负责人 |
|---|---|---|---|---|---|---|---|---|
| MET-01 | OBJ-01 | 过程 | 受邀体验人员中完成录音、提交并播放最新作品的人数占比 | 无 | 首轮不少于 5 人完成，或不少于 70% 受邀者完成 | 埋点 / 体验记录 | 首轮内部体验 | 产品 |
| MET-02 | OBJ-01 | 结果 | 体验者是否能描述“多人异步提交后自动合成”的玩法 | 无 | 访谈中多数体验者能复述核心玩法 | 访谈记录 | 首轮内部体验 | 产品 |
| MET-03 | OBJ-02 | 护栏 | 微信主链路被录音授权、上传或提交失败阻断的比例 | 无 | 首轮不出现系统性阻断；个别失败可定位 | 日志 / 反馈 | 首轮内部体验 | 研发 |

达标时进入下一轮产品化评估；若 MET-03 不达标，优先补技术链路，不扩大体验范围；若 MET-01 达标但 MET-02 不达标，优先调整页面说明和合唱结果反馈。
