评审入口

问题

用户在活动详情页直接尝试报名，无法提前理解圈内优先阶段和等待条件。

目标

让用户在点击前理解当前是否可报名，同时保留点击时的实时资格校验。

范围

活动详情页报名链路、资格展示状态、相关埋点和 FAQ。

非目标

不改变资格、名额、排序、通知和活动创建规则。

评审关注

摘自正式 PRD 的风险 / 待确认项
  • 详情展示状态与点击时的实时资格不一致时如何收口 PRD 0.2
  • 公开报名时间字段是否统一；无字段时使用什么兜底文案 PRD 8.1
  • 用户是否会把“可报名”理解为已有名额 PRD 8.1

    0.2 一页结论

    • 一句话方案：在圈子活动详情页报名区，根据用户身份提前展示优先报名资格，减少无效报名尝试和资格咨询。
    • 已确认目标与方案：让用户点击前理解当前是否可报名；复用服务端现有资格判定，不改变报名资格规则。
    • 关键取舍与非目标：本期不改活动列表、规则正文和名额分配机制。
    • 本次交付范围与版本：iOS、Android 详情页、资格展示状态、相关埋点和 FAQ，随 v3.8.0 发布。
    • 效果判断标准：资格限制返回率和资格咨询量下降，符合资格用户报名转化不明显受损。
    • 用户主路径与页面影响：入口 → 活动详情 → 查看资格 → 报名 / 等待；本次只改活动详情页。
    • 关键信息结构变化：在报名区域附近新增资格说明，活动最终状态仍优先展示。
    • PRD / spec 边界：PRD 确认资格展示状态、页面表现、实时校验原则和验收；具体接口字段、状态枚举命名、兼容实现和监控实现交给研发 spec。
    • 最大风险：详情展示状态与用户点击时的实时资格可能不一致。

    3.3 功能需求明细

    本节按照“需求结论 → 行为步骤 → 条件分支 → 异常与边界 → 追溯”编写。规则表和原型用于补充，不代替正文。

    FR-01 生成资格展示状态

    需求结论

    登录用户每次请求圈子活动详情时，服务端同时返回一个唯一的资格展示状态，客户端直接按该状态渲染，不在本地重新计算资格。这个状态只用于解释当前页面应如何展示；用户真正点击报名时，报名接口必须再次根据最新活动阶段、成员身份、报名状态和名额情况校验，详情页状态不能直接作为报名凭证。

    行为说明

    1. 用户首次进入详情页、主动刷新页面或页面因其他操作重新请求详情数据时，服务端重新计算资格展示状态；页面停留期间不额外轮询。
    2. 对圈子活动，服务端使用活动最终状态、当前报名阶段、用户是否已报名、用户圈内成员身份和公开报名时间参与判断，并在详情响应中返回唯一的 eligibility_display_state；非圈子活动不返回该新增状态字段，客户端继续使用既有报名状态渲染。
    3. 客户端收到状态前，报名区域展示加载占位，不提前显示“可报名”或“不可报名”；收到状态后一次性替换为 FR-02 对应内容。
    4. 用户点击可用的报名按钮时，客户端提交报名请求；服务端按点击时的最新数据重新校验。若实时结果与详情页展示不一致，以报名结果为准，页面随后刷新详情状态。

    状态判定与优先级

    优先级进入条件返回状态状态含义
    1活动已取消、已结束或已超过报名截止时间closed当前不允许继续报名；具体结束原因由活动状态决定
    2活动仍可访问，当前用户已经报名成功registered用户无需再次报名
    3圈内优先报名阶段，用户为圈内成员member_available当前具备优先报名资格，但仍不代表名额锁定
    4圈内优先报名阶段，用户明确不是圈内成员non_member_waiting当前不能报名，等待公开报名
    5圈内优先报名阶段，但成员身份无法确认identity_unknown页面无法可靠判断资格，需要重试或在点击时实时校验
    6已进入公开报名阶段，且活动未关闭、用户未报名normal_registration不再区分圈内身份，用户可以提交报名

    只要命中更高优先级状态，就不再计算低优先级状态。例如活动已截止时，即使用户是圈内成员，也必须返回 closed。

    异常与恢复

    异常条件用户看到什么系统 / 数据处理恢复方式
    详情请求整体失败页面级错误提示“活动信息加载失败”，不展示报名按钮不生成资格展示状态，不写入报名数据用户点击“重新加载”后重新请求详情
    仅成员身份获取失败返回 identity_unknown，页面不展示肯定性资格结论记录身份查询失败；不修改成员关系和报名状态用户可刷新资格，也可点击报名交由报名接口实时校验
    页面展示后活动阶段或身份变化页面可能短暂保留旧展示报名接口使用最新数据校验，不信任旧展示状态返回明确报名结果，客户端刷新详情并更新展示

    保持不变与边界

    • 本功能不改变报名资格、成员关系、名额计算和报名结果规则，只增加详情页展示所需的派生状态。
    • 非圈子活动不返回 eligibility_display_state，继续使用普通活动详情中的报名状态和既有报名按钮。
    • 旧客户端忽略新增字段，仍通过报名接口获得最终结果。

    追溯：PAGE-01 / IA-01、IA-02；UI-03；RULE-01 至 RULE-04；AC-01 至 AC-04。

    FR-02 根据资格状态展示说明和报名操作

    需求结论

    活动详情页在活动基础信息与报名按钮之间增加资格说明区，让用户在点击前知道当前是否可报名、为什么以及下一步能做什么。资格说明、按钮状态和点击结果必须由同一个 eligibility_display_state 驱动，不能出现文案提示“可报名”但按钮不可用，或提示“等待开放”但按钮仍可提交的矛盾状态。

    页面行为与分支

    展示状态资格说明区主按钮与可操作性用户操作后的结果状态切换与优先级
    member_available显示“当前为圈内优先报名阶段，你可优先报名”；不使用“已获得名额”等承诺性文案显示“立即报名”，可点击点击后提交实时报名校验；成功进入报名结果页，失败留在详情页并展示服务端原因活动关闭时切换为 closed；活动未关闭但用户已报名时切换为 registered
    non_member_waiting有公开报名时间时显示“当前为圈内优先报名，MM月DD日 HH:mm 后开放报名”；无时间时显示“当前为圈内优先报名，公开报名后你可参与”显示“等待开放”，不可点击不发起报名请求到达公开报名阶段并刷新后切换为 normal_registration；活动关闭优先切换为 closed
    identity_unknown显示“暂时无法确认你的报名资格，请刷新后重试”；提供“刷新资格”文字操作显示“报名”，可点击，但不展示“可优先报名”“刷新资格”重新请求详情；点击“报名”直接进入实时报名校验，成功或失败均以接口结果收口身份恢复后切换为成员或非成员状态；活动关闭仍最高优先
    normal_registration不展示圈内优先说明，资格说明区整体收起显示“立即报名”，可点击点击后提交实时报名校验；成功进入结果页，失败留在详情页并显示原因用户报名成功后切换为 registered；活动关闭切换为 closed
    registered显示“你已报名”，不再展示资格限制说明显示“已报名”，不可点击不重复提交报名请求活动关闭时页面同时展示活动最终状态，但保留已报名结果入口
    closed根据原因显示“报名已截止”“活动已结束”或“活动已取消”显示对应最终状态，不可点击不发起报名请求最高优先级，不再展示资格提示

    点击反馈与恢复

    1. 可点击按钮提交后立即进入加载状态并禁止重复点击，直到报名请求返回。
    2. 报名成功时进入报名结果页；返回详情页后应展示 registered。
    3. 因资格、活动阶段或名额变化失败时，用户停留在详情页，页面展示服务端返回的明确失败原因，并自动刷新详情状态；不得只提示“操作失败”。
    4. 因网络错误或超时失败时，页面提示“网络异常，报名结果尚未确认，请重试”；按钮恢复可点击。客户端不得在未收到成功结果时展示已报名。
    5. 用户离开后重新进入详情页，以新详情请求结果为准，不复用上次页面中的资格状态。

    保持不变与边界

    • 不修改活动列表卡片、活动规则正文、名额计算和消息提醒。
    • 资格区只解释当前状态，不承诺最终名额；原型 UI-01、UI-02 只定义布局和视觉，以上行为与优先级以本节为准。

    追溯：PAGE-01 / IA-01、IA-02；UI-01、UI-02；RULE-01 至 RULE-04；AC-01 至 AC-04。

    FR-03 记录资格说明和报名链路事件

    需求结论

    埋点用于判断资格说明是否被真实看到、用户是否继续报名以及最终结果，不能影响页面展示和报名主流程。每条事件都必须带同一次页面访问和报名请求的关联标识，保证曝光、点击和结果可以组成漏斗，并避免页面重复渲染造成重复曝光。

    事件定义

    事件精确触发时机单次触发规则必填参数失败处理
    priority_eligibility_hint_viewmember_available、non_member_waiting 或 identity_unknown 的资格说明实际进入可见区域时同一 page_view_id 下，同一展示状态只记一次；状态变化后可记录新状态page_view_id、activity_id、eligibility_display_state、activity_phase、membership_status、entry_source、client_version上报失败不影响页面；由埋点 SDK 重试，不重复生成业务动作
    activity_signup_click用户点击可用报名按钮且客户端准备发起报名请求时每次有效点击记一次；按钮加载期间的重复点击不记录上述公共参数、request_id、按钮文案上报失败不阻止报名请求
    activity_signup_result客户端收到该 request_id 对应的报名成功、业务失败或网络失败结果时一个 request_id 只记一次最终结果上述公共参数、request_id、result、failure_code；成功时 failure_code 为空上报失败不改变报名结果；进入埋点错误日志

    membership_status 只记录 member、non_member、unknown，不上传成员证明或其他身份原始数据。result 取值为 success、business_failure、network_failure；业务失败必须记录可聚合的 failure_code，不能只传自由文本。

    验收方式

    测试环境按一次页面访问执行“看到提示 → 点击报名 → 收到结果”，使用 page_view_id 和 request_id 核对三类事件能够串联；重复触发页面渲染不得产生第二条同状态曝光，连续点击被按钮防重拦截时不得产生额外点击事件。关闭或模拟埋点上报失败后，页面展示和报名结果必须保持正常。

    保持不变与边界

    • 不回填历史事件；旧客户端仍上报原有报名点击和结果事件，新参数允许为空。
    • 本功能不采集新的个人敏感信息，不以埋点成功作为报名成功条件。

    追溯：SCN-01、SCN-02；MET-01、MET-02、MET-03；AC-05。

    6.2 研发验收标准

    AC-01 圈内成员看到可执行的优先报名状态

    • Given：活动处于圈内优先报名阶段、未关闭，登录用户为圈内成员且尚未报名。
    • When：用户进入活动详情页，详情请求成功返回 member_available。
    • Then：资格区展示“当前为圈内优先报名阶段，你可优先报名”，按钮显示“立即报名”且可点击；点击后按钮进入加载态并只提交一次请求。报名成功进入结果页，返回详情后展示 registered。

    AC-02 圈外用户得到明确的等待条件

    • Given：活动处于圈内优先报名阶段、未关闭，登录用户明确不是圈内成员且尚未报名。
    • When：用户进入详情页，详情返回 non_member_waiting。
    • Then：有公开报名时间时展示具体时间，无时间字段时展示不含具体时间的兜底文案；按钮显示“等待开放”、不可点击，且不产生报名请求。进入公开报名阶段并刷新后，状态切换为 normal_registration，按钮变为“立即报名”。

    AC-03 未知身份和实时结果能够明确收口

    • Given：优先报名阶段的成员身份查询失败，或页面展示后身份、活动阶段、名额发生变化。
    • When：详情返回 identity_unknown，用户刷新资格或点击报名；或者用户从其他可报名状态点击报名。
    • Then：未知身份时页面不得展示“可优先报名”；刷新操作重新请求详情，报名操作由报名接口实时校验。业务失败时用户留在详情页并看到可理解的具体原因，页面自动刷新状态；网络失败时提示结果尚未确认、按钮恢复可点击，未收到成功结果前不得展示已报名。

    AC-04 最终状态、已报名和非圈子活动不受资格提示干扰

    • Given：分别准备活动已截止 / 已结束 / 已取消、用户已报名、非圈子活动三组数据。
    • When：用户进入详情页。
    • Then：最终活动状态优先展示对应“报名已截止”“活动已结束”或“活动已取消”，按钮不可点击；已报名用户展示“你已报名”和结果入口，不重复提交；非圈子活动不展示圈内资格说明，并继续使用普通活动的报名状态和报名接口。

    AC-05 埋点可串联、可去重且不阻塞主流程

    • Given：测试环境能够查看客户端事件，并可模拟埋点上报失败。
    • When：同一次页面访问中展示资格提示、触发重复渲染、点击一次报名并收到结果；随后模拟埋点上报失败重复执行主流程。
    • Then：同一 page_view_id 和展示状态只有一条曝光；一次有效点击对应一条带相同 request_id 的点击和结果事件；加载期间重复点击不产生额外事件；事件参数符合 FR-03，三类事件可串联。埋点失败时页面展示、报名请求和报名结果均不受影响。
