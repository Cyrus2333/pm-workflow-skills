# 飞书发布与渲染

> 本文档是飞书交付的唯一主源：画板承载规则、mermaid/SVG 输入格式、资源预览与正文阅读态的双面验收。
> 何时读取：用户要求创建、更新或验收飞书文档时（可叠加于任一路径）。

## 1. 适配层边界

仅在用户要求创建、更新或验收飞书文档时使用本指南。产品事实、内容架构和视觉语义在发布前已经确定；飞书层只负责落版和证明最终结果可读。飞书文档和画板不是新事实源，平台限制不能变成通用 PRD 规则。

用户要求输出飞书文档时，飞书文档是唯一主交付面；本地 Markdown、XML、Mermaid、SVG 和 JSON 是构建源，不再作为并列主文档。飞书适配不得把传统 PRD 改写成平台展示简报。

## 2. 快速路由

| 飞书路径 | 适用情况 | 必须动作 |
|---|---|---|
| 日常发布 | 普通新建/更新，正文为主或只有简单表格 | 写入 → 回读关键结构 → 打开阅读视图抽查 |
| 视觉发布 | 文档包含图片、流程图、状态图、原型或画板 | 日常发布 + 逐个查看本轮新增/修改的视觉 |
| 严格发布 | 正式评审门禁、重要版本、重复自动发布或用户明确要求审计 | 视觉发布 + 结构化审计 + 独立读者测试 |

默认选择满足风险的最轻路径。飞书审计 JSON、自动采集器和独立读者测试不属于每次发布的必做项。

## 3. 日常发布

```text
本地成稿
→ 编译为飞书标题/段落/列表/表格
→ 创建或定向更新
→ 回读目标章节
→ 打开最终阅读视图抽查
```

回读至少确认：

- 标题与主要章节存在且顺序正确；
- 关键结论、表格、链接和引用没有丢失；
- 没有重复标题、空标题、占位符或内部检查日志；
- 文档在目标阅读视图中可以连续阅读。

日常发布无需创建执行包、飞书审计文件或独立读者记录。

## 4. 视觉发布

在日常发布基础上，对本轮新增或修改的每张视觉执行：

1. 从飞书回读结果取得图片或画板 token；
2. 导出/预览飞书中的最终资源，不能只看本地源文件；画板 preview 当前通常返回 JPEG，输出文件优先省略扩展名，或先确认响应格式再使用 `.jpg`，不要预设 `.png`；严格审计时以 `<board-token>.<ext>` 命名，便于自动采集；
3. 实际检查中文、字号、裁切、连线、状态差异和画布空白；
4. 在正文实际宽度下检查是否仍能回答对应读者问题；
5. 不清楚时重排、拆成总览与局部，或将复杂全景改为独立下钻。

画板资源预览和文档阅读视图是两个证据面，不能互相代替：

- 资源预览证明节点、文字、连线和画布内容在飞书画板中存在；
- 文档阅读视图证明画板插入位置、正文缩放和周边说明在实际阅读宽度下成立；
- 飞书 preview 可能使用固定近方形导出画布，宽图底部留白不必然等于正文嵌入留白；先在阅读视图复核再决定是否重排；
- 阅读视图因登录、加载或浏览器不可用而未完成时，发布状态只能记录为“资源渲染通过、阅读态待验”，不得把 preview 检查写成完整发布通过。

正文宽度检查与放大检查分开：

- 总览流程和局部故事板在正文中无需放大即可阅读；
- 完整交互全景可以依赖画板缩放，但正文必须另有可读的总览和局部解释；
- 不能用一个可放大的复杂画板替代产品动线和详情原型。

未变化的既有视觉不必每次全部重验；但修改其来源规则、布局或引用位置时必须重新检查。

## 5. 严格发布

只有满足快速路由中的严格条件时，才保存结构化发布证据：

```bash
python3 scripts/audit/build_feishu_audit.py \
  --fetch-json /absolute/path/to/lark-fetch.json \
  --document-url https://example.feishu.cn/docx/xxxxxxxx \
  --preview-dir /absolute/path/to/exported-previews \
  --out /absolute/path/to/feishu-delivery-audit.json

python3 scripts/audit/check_feishu_delivery.py \
  --audit /absolute/path/to/feishu-delivery-audit.json
```

使用 `assets/feishu-delivery-audit-template.json`。构建器只提取文档、版本和画板 token，并把尚未人工确认的项目初始化为失败；实际查看后才能改为通过。严格发布还要让无本轮上下文的读者只读最终飞书文档，回答预设评审问题。

审计检查器验证证据结构和未解决失败，不能代替人工视觉判断。测试这个 skill 本身时也可以使用严格发布，但测试要求不得反推为所有用户的默认动作。

## 6. 正文与视觉选型

### 正文块

- 章节使用标题；字段或一句话要点使用加粗引导句，不升成目录项。
- 背景、分析和过渡保持连贯段落；并列步骤才使用列表。
- 条件、职责、状态差异和字段口径具有真实行列关系时使用表格。
- 高亮块只承载不看就可能误判的结论或风险，不作为每节装饰。
- 分栏只用于信息量相当且确需并排比较的短内容。

从零创建默认使用飞书 XML 表达块结构；用户提供 Markdown 文件或明确要求 Markdown 时按用户要求。不要把 Markdown 机械导入后就结束，仍需检查飞书块结构。

### 视觉资产

**飞书交付时，主流程图与页面交互总览的主载体是飞书原生画板，不是图片。** 本地自研渲染管线（`render_flow_diagram.py` / `render_overview_board.py` → PNG）负责语义检查、发布前预览和发布审计证据；进入飞书正文时，流程/总览类视觉用画板承载（读者可缩放、可追踪、可小改），本地 PNG 不贴进正文冒充主交付。手机屏原型（关键页面故事板）继续使用图片块——画板承载手机壳组件会损失保真，且原型不需要读者编辑。

mermaid 在飞书场景是**画板的输入格式**，不是本地渲染依赖：流程 spec 用 `scripts/export_flow_mermaid.py` 导出 mermaid DSL，再经画板导入完成发布；这与"本地渲染不依赖 mermaid-cli"不冲突。页面交互总览属于"精确布局的组合图"，默认走 SVG 画板：`scripts/render_overview_board.py --svg` 输出的纯 SVG 与正文 PNG 预览同源同布局（迷你屏、聚合排布、图例全部保留）；注意飞书画板的 SVG 导入只保留原生 SVG 图元（foreignObject、脚本、外部资源会被丢弃，已实测验证），不要把 HTML 包进 SVG 上传。

| 评审任务 | 飞书表达 | 选择条件 |
|---|---|---|
| 简洁流程、状态或时序 | Mermaid 画板 | 源码能完整表达且最终预览清楚 |
| 精确布局的流程、泳道、原型或组合图 | SVG 画板 | 自包含 SVG 经飞书解析仍稳定 |
| 截图、设计稿或必须固定像素的视觉 | 图片块 | 保真比可编辑更重要 |
| 复杂交互全景 | 正文总览 + 局部图 + 独立下钻 | 全景在正文宽度下无法读清 |

SVG 避免外部资源、脚本、`pattern`、`clipPath`、`mask` 和非阴影用途的复杂 filter；文字使用真实 `<text>`。

优先采用以下分工：

1. 端到端流程、简单泳道或状态关系：Mermaid 画板；
2. 页面信息和连续关键帧：SVG 画板；
3. 复杂完整交互：独立可缩放画板，正文保留总览和对应任务局部图；
4. 真实截图或最终设计稿：图片块或设计文件链接。

这套分工可以复用，但具体图型、方向、分区和数量仍由当前读者问题决定。

## 7. 安全更新

使用当前认证的 `lark-cli`，默认以用户身份操作。已有文档优先定向更新：

1. `docs +fetch --scope outline` 定位章节；
2. `--scope section --detail with-ids` 读取目标节；
3. 使用 block 指令修改；
4. 更新后重新 fetch，不能假设旧 block ID 一直有效。

`overwrite` 可能改变标题并丢失图片、画板、评论或引用。只有用户明确要求整篇覆盖、保护资源已盘点且可以重建时才使用。

更新已有画板时复用稳定 board token；同一次逻辑更新复用同一个 `idempotent-token`。覆盖画板前先导出 source/raw/preview，确认它是可覆盖的流水线资产，不包含需要保留的人工标注。

## 8. 返工路由

- 标题、段落或表格失序：修正飞书块装配或插入位置；
- 正文冗长、重复：回到内容架构和压缩；
- 图中事实错误：回到正式 PRD、事实集或交互模型；
- 图型不能回答问题：重新选择表达；
- 画布空白过多或正文缩略过小：重排、拆图或改为下钻；
- 全景可放大但正文仍不理解主线：补产品动线和局部故事板，不继续放大全景；
- SVG 解析错位：简化不兼容特性，仍不稳定时改用固定图片；
- 更新破坏既有资源：停止继续写入，从版本历史恢复并改用 block 级更新。
