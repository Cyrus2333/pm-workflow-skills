## 1. 上下游契约

`pm-prd-write` 负责确认产品行为，至少提供 Page / Surface、IA / Section、用户可见状态、操作、状态迁移、异常恢复和验收来源；其"页面状态与操作矩阵"是本模型状态定义的首选候选来源（承接取舍见[转译与文档结构](./转译与文档结构.md) §4）。`pm-collaboration-deliver` 只能编译和表达这些事实：可以设计画板布局、分组、图文位置和视觉层级，不得新增页面行为、业务状态、按钮结果或恢复规则。

正式 PRD 缺少会改变用户结果的页面状态、操作或迁移时，停止生成原型并返回上游补齐。不能用看似完整的低保真页面替代产品结论。

截图、现有页面和参考案例只能补充可观察的页面结构与视觉上下文，不能替代上述交互规格。原型执行前按[视觉与原型](./视觉与原型.md)判断产品语义充分度和设计权限。

## 2. 四层交互模型

复杂界面需求使用以下四层，不再把“页面”和“状态”混为一个对象：

| 层 | 回答的问题 | 示例 |
|---|---|---|
| Surface / Page | 用户在哪个载体或页面完成任务 | Push、消息详情、调整页、结果页 |
| State | 该载体在当前条件下具体呈现什么 | 校验中、可提交、提交中、成功、资格失效 |
| Action | 用户此刻能执行什么 | 查看方案、确认、取消、联系班主任 |
| Transition | 什么事件或条件把当前状态带到哪里 | 点击确认后进入提交中；失败后进入统一拦截 |

页面是稳定容器，状态是用户在某一时刻看到的完整表现。一个页面通常包含多个状态；同一状态若在布局、主操作、反馈或恢复路径上发生明显变化，应分别建模。

每个状态声明 `visibility`，决定它在页面交互总览中的呈现粒度：`page`（用户可停留、可决策的稳定表现，渲染为页面卡片）、`transient`（加载/校验/提交处理中，一闪而过、无稳定布局，渲染为 chip 扁条，不画手机屏；纯路由判断可用 system 节点）、`external`（既有外部页面或出口，渲染为简化出口卡片）。

## 3. 状态拆分规则

出现以下任一变化时拆成独立状态：

- 主信息、主操作或按钮可用性变化；
- 加载、空态、失败、成功、已完成或资格拦截；
- 弹层覆盖、提交中、防重复或异步结果等待；
- 返回、取消、关闭、刷新或再次进入后的用户结果不同；
- 同一页面因条件不同而需要不同提示或恢复动作。

只有数据值或短文案变化，且布局、可用操作、结果和恢复均相同时，才允许共用状态，并在规则表中列条件差异。

复杂交互至少主动检查：入口、加载、默认/可操作、确认、处理中、成功、失败、空态、已完成、资格失效、返回/取消、再次进入。它们不是固定必填项；不适用时写清原因，不能静默遗漏。

## 4. 迁移与操作规则

每条迁移写清：来源状态、触发事件、条件（如有）、目标状态、类型和正式 PRD 来源。触发使用产品语言，例如“点击确认调整”“CRM 明确返回成功”，不能只写“下一步”。

强制规则：

1. 每个可用操作必须对应一条迁移或明确的外部出口；
2. 每个非终态至少有一个出口；
3. 每个异步处理中状态同时覆盖成功和失败结果；
4. 所有需要展示的状态都必须从入口可达；
5. 返回、取消、刷新、重试和再次进入不能依赖作者口头说明；
6. 迁移不能新增正式 PRD 未确认的业务判断。

终态表示当前任务已经结束，不等于页面没有按钮。终态中的“返回首页”“联系人工”等操作仍应以外部出口或下一状态表达。

## 5. 完整模型与展示子图

### 5.1 完整模型

完整交互模型保存全部载体、状态、动作和迁移，是查漏和跨产物同源依据。它不等于正文必须出现的图，也不要求把所有状态渲染成手机页面卡片。

模型必须完整；展示层可以按读者问题抽取子集。多个原因进入同一结果时可以在展示层收敛，但模型仍保留每条来源迁移。

### 5.2 页面交互总览

多页面、多分支需求在产品主流程与局部故事板之间增加页面交互总览。它回答：用户此刻在哪个页面或关键页面状态、能做什么、动作或条件把他带到哪个页面状态、失败/返回/重进最终落在哪里。

页面交互总览必须具备：

- 页面或关键页面状态卡片，而不是只有抽象流程节点；
- 页面卡片使用可识别的缩略界面结构，可见当前任务、关键内容、主次操作和状态反馈；只有标题加状态文案的框不算页面卡片；
- 卡片间每条连线标注用户动作、系统事件或互斥条件；
- 主操作沿稳定阅读方向，分支终态靠近分歧点，长回边使用不同线型并避免穿过页面；
- 多个原因进入同一页面状态时可以聚合为一条带原因组的连线，但底层迁移 ID 全部映射；
- 多个状态共用同一页面卡片时，不能只把状态 ID 塞进同一个数组：若奖励、文案、操作或后续结果有可见差异，使用 `state_variants` 逐项说明并在图中显式呈现；只有页面表现和读者结论确实相同时，才可声明 `visual_equivalent=true` 并解释等价原因；
- 外部页面可以使用简化出口卡片，不重画其内部布局；
- 从同一交互模型生成，页面状态和连线分别映射状态与迁移；
- 瞬态（加载中、校验中、提交处理中等 `visibility=transient` 的状态）不是页面：它们没有稳定布局、不可停留、不承载用户决策，一律用 `chip` 形态的扁条节点承载，不渲染手机屏内容；纯路由判断（如打开时判断去向）虽是瞬态，但语义上是系统决策点，可用 `system` 节点承载。`chip` 只能装瞬态状态，页面状态不得用 `chip` 降级；
- 总览卡片上的屏幕内容应与第 4 章需求详情的故事板同源：当需求已产出 screens 格式的线框/故事板 spec 时，总览 spec 声明 `screen_source` 指向它，页面卡片用 `screen_ref` 引用其中的屏幕 ID，由渲染器取同一份块定义，两处不各写一份；当需求没有同源故事板 spec（如轻量需求、故事板为 boards 格式的旧资产）时，页面卡片直接写内联 `screen`（任务、关键内容、操作），保证读者不翻页也能看懂每张卡片。

使用 `assets/page-interaction-overview-template.json` 记录映射，并运行 `scripts/check_page_interaction_overview.py --overview <spec>`。渲染产物（`render.source_path` / `preview_path` 指向的 SVG/PNG）默认要求真实存在；spec 先行、渲染未执行或渲染产物未随包保存时，加 `--no-file-check` 只校验结构与交互模型映射（与 `check_prototype_plan.py` 的同名参数语义一致）。`coverage_mode=review_complete` 时，全部状态和迁移都必须由某个页面卡片或连线承载；同一结果的多条迁移可以收敛到一条可视连线。页面交互总览不是一张固定尺寸大图，布局、页面数量和分区必须随需求设计。

`coverage_mode=review_complete` 的总览首先是完整核查/索引资产。若它在正文目标宽度下不可读，必须保持 `delivery_role=zoomable`，正文只放可读的分区预览、聚焦子图或主流程，并提供下钻入口；禁止把完整图原样缩小后当作正文唯一解释。

### 5.3 其他展示子图

根据阅读问题选择表达：

- 用户从入口到主要结果：产品动线；
- 页面、页面内状态与跳转逻辑：页面交互总览；
- 一个任务的连续页面反馈：局部交互故事板；
- 一个对象的完整生命周期：状态图；
- 跨模块全部页面和迁移：独立可缩放全景，仅在确有核查需要时生成。

展示子图声明 `coverage=focused`，并用 `focus_state_ids`、`focus_transition_ids` 列明从模型抽取的状态和迁移；完整全景声明 `coverage=complete`。底层完整性由模型检查器证明，不能要求页面主图或局部故事板覆盖全部迁移。

声明为完整交互画板的资产必须保留可检查的画板规格，并把可视状态映射为画板节点、把可视状态之间的迁移映射为带动作或条件的连线。只有页面卡片而没有迁移连线的资产是状态概览，不能称作交互图。

### 5.4 局部原型

总览流程建立全局心智；需求详情使用“原型/状态—信息项—交互与逻辑”就近说明。一个规则会改变按钮、提示或页面反馈时，把对应状态放在同一行，不把所有图片集中放在文档前部。

低保真图只确认信息层级、状态、操作和反馈位置。没有设计系统或已确认设计稿时必须标注“结构示意，不代表最终布局”。

## 6. 自动门槛

交互模型至少阻止：

- 页面与状态引用断裂；
- 状态或迁移 ID 重复；
- 可用操作没有去向；
- 非终态没有出口；
- 异步处理中缺成功或失败；
- 存在从入口不可达的状态；
- 必需状态类型缺失；
- 需要视觉表达的状态没有原型引用。
- 展示子图引用不存在的状态或迁移；
- 完整交互画板缺少可检查规格，或模型中的可视迁移没有画板连线；
- 多页面交互版缺少页面交互总览且没有明确不适用理由；
- 页面交互总览遗漏入口、可视状态、终态、可用操作迁移或返回/重进；
- 总览连线的来源和目标页面与底层迁移不一致；
- 局部故事板声称完整覆盖，却没有承载全部模型迁移；
- 正文把不可读的完整全景当作唯一交互解释。

自动检查证明结构闭环，不证明产品规则正确。完成前仍要人工查看总图，核对主路径、分支邻近性、连线交叉、字号、页面状态差异和最终平台缩放后的可读性。

若页面总览结构检查通过，但页面卡片无法让读者识别页面任务、信息层级和可用操作，仍判定不通过并退回原型设计层；不得以状态和迁移覆盖率替代页面表达质量。
